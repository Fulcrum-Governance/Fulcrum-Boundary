# Fulcrum Boundary v0.12.0

`v0.12.0` is the public-verifier and release-provenance release. It preserves
the product boundary: MCP remains the production adapter; every other adapter
and profile remains preview; protection applies only to actions routed through
Boundary; and Boundary does not emit `proved` decisions.

## Highlights

- `fulcrum-verify-witnessed` is now a public, Apache-2.0, independently
  buildable nested Go module. It checks an exported witnessed-log bundle
  offline against locally supplied Fulcrum and witness Ed25519 public keys,
  with no Fulcrum account, credential, network call, or private-code import.
  This closes the code/license gate only. Current witnesses remain
  Fulcrum-operated on separate infrastructure; the verifier does not establish
  independent witness operation.
- Secure GitHub gains an L0-L3 bypass-proof ladder and fail-closed evidence
  packet, plus a narrow stateful route to the official GitHub MCP endpoint.
  The route governs one configured untrusted source issue and protected target,
  exposes only `issue_read` and `create_or_update_file`, and denies a protected
  write after a successful configured read before forwarding. It does not
  semantically classify issue prose, cover the full tool catalog, close direct
  GitHub bypasses, or change Secure GitHub's preview status.
- The `proof-receipt-v0.1` sidecar binds checker-validated budget and static
  privilege invariant lines to a decision record. It is attached invariant
  evidence, not a proved decision mode, and does not change `decision_hash`.
- Public language now distinguishes wired witness evidence, trust-termination
  transition consistency, and the design-only equilibrium analysis without
  claiming runtime proof.
- Per-host routing tutorials cover Claude Desktop, Claude Code, Cursor, and VS
  Code. Windows permanently ships only the static build: routed SQL classifies
  `UNKNOWN` and is denied fail-closed when the cgo classifier is unavailable.
- Kernel escalation await mode and the additive pipeline seam preserve
  fail-closed behavior across timeout, cancellation, duplicate request, and
  publish/subscribe faults.
- The root, gRPC, and verifier modules are verified with the Go 1.26.5
  toolchain; dependency and workflow security pins are refreshed.
- Release packaging uses GoReleaser's current multi-platform container and
  Homebrew cask pipes. The install command remains
  `brew install fulcrum-governance/tap/boundary`; the tap's legacy formula must
  be migrated before tag approval.

## Install after publication

```bash
brew install fulcrum-governance/tap/boundary
docker pull ghcr.io/fulcrum-governance/boundary:v0.12.0
go install github.com/fulcrum-governance/fulcrum-boundary/cmd/boundary@v0.12.0
```

The root release publishes static archives for macOS, Linux, and Windows;
native-cgo full-classifier archives for macOS and Linux; `SHA256SUMS` and
`SHA256SUMS-cgo`; one SPDX SBOM per archive; a fixture-safe Boundary evidence
bundle; a static multi-architecture container; and a static Homebrew cask.
The static build has reduced SQL-classification capability but keeps a
fail-closed deny posture.

Install the nested verifier from its source-distribution tag:

```bash
go install github.com/fulcrum-governance/fulcrum-boundary/verify-witnessed@v0.12.0
```

Go resolves that module from `verify-witnessed/v0.12.0`. The root `v0.12.0`
and nested `verify-witnessed/v0.12.0` tags must point to the same exact commit.
The verifier does not have its own prebuilt archive, container, Homebrew
package, or version flag.

## Supply-chain verification

Each static and native-cgo archive has an SPDX SBOM. The release workflow
records GitHub build-provenance attestations for the configured static
archives, static SBOMs, `SHA256SUMS`, native-cgo archives, and native-cgo SBOMs.
Verify checksums first, then use `gh attestation verify` as documented in
[`docs/SUPPLY_CHAIN.md`](../SUPPLY_CHAIN.md). Distribution provenance is
distinct from runtime decision-record signing and does not prove verdict
correctness or execution.

## Compatibility and limitations

- This is a pre-1.0 release. Read `CHANGELOG.md` for the full
  `v0.11.0..v0.12.0` delta.
- Direct tool paths that bypass Boundary remain outside its control.
- Secure GitHub, Command Boundary, Edit Boundary, CLI, CodeExec, gRPC, Managed
  Agents, Webhook, and A2A remain preview.
- The verifier checks the bundle it receives. It does not prove bundle
  completeness, upstream correctness, legal admissibility, immutability, or
  organizational independence of a witness.
