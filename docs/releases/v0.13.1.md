# Fulcrum Boundary v0.13.1

> **Published release — 2026-09-02.** The public GitHub release is not a draft
> or prerelease. The annotated `v0.13.1` and
> `verify-witnessed/v0.13.1` tags both peel to
> `8a5762888be8404f8a4a0e64a2ad6206667b71b6`.

**Auto mode decides. Boundary keeps the receipts.**

`v0.13.1` is a patch release. Its only product-behavior fix over `v0.13.0` is
the installer checksum-selector repair below. The tagged release delta also
contains the accompanying documentation and release-metadata reconciliation
across four commits and 30 files. It changes no Boundary enforcement behavior,
classifier, hook semantics, adapter maturity, or claim status: Session
Receipts and the Claude Code hook first shipped in `v0.13.0`, MCP remains the
production adapter, Command Boundary and Edit Boundary remain delivered
previews, protection applies only to actions routed through Boundary, records
are hash-verifiable for covered-field integrity only — not authenticity,
correctness, or execution proof — and Boundary does not emit `proved`
decisions.

## The fix

The `v0.13.0` one-line installer's direct-release lane failed on every
published static archive. It selected the `SHA256SUMS` entry with an
unanchored fixed-string match, which also captured the archive's
`<archive>.spdx.json` SBOM line — the archive filename is a prefix of the
SBOM filename — and `shasum -c` then failed on the never-downloaded SBOM. The
failure was fail-closed: the installer refused to install and wrote no
binary, receipt, or partial state. The published archives and checksum
manifest themselves were, and are, correct; the Homebrew lane was unaffected.

`v0.13.1` ships the repaired installer: the manifest entry is selected by the
complete filename field, and exactly one exact entry is required — zero or
duplicate exact entries still refuse to install. Hermetic regression tests
drive the real direct-release lane against a collision-shaped manifest,
including the release-download receipt and the receipt-driven uninstall round
trip.

The immutable `v0.13.0` tag retains the defective installer; it is not
repaired in place. Installing from the `v0.13.0` tag's checkout script keeps
the failure; the raw-`main` installer and the `v0.13.1` release carry
the fix.

## Install

These commands target the published `v0.13.1` release:

```bash
brew install fulcrum-governance/tap/boundary
docker pull ghcr.io/fulcrum-governance/boundary:v0.13.1
go install github.com/fulcrum-governance/fulcrum-boundary/cmd/boundary@v0.13.1
```

Install the nested verifier from its published source-distribution tag:

```bash
go install github.com/Fulcrum-Governance/Fulcrum-Boundary/verify-witnessed@v0.13.1
```

The verifier does not have its own prebuilt archive, container, Homebrew
package, or version flag.

## Compatibility and limitations

- This is a pre-1.0 release. Read `CHANGELOG.md` for the
  `v0.13.0..v0.13.1` delta; the `v0.13.0` notes carry the full Session
  Receipts and hook story with its limitations.
- Direct tool paths that bypass Boundary remain outside its control; the hook
  governs only the tool calls it is wired to intercept.
- Secure GitHub, Command Boundary, Edit Boundary, CLI, CodeExec, gRPC, Managed
  Agents, Webhook, and A2A remain preview.
- The founder-controlled immutable public-install smoke passed on 2026-09-02.
  Public raw `main` and immutable `v0.13.1` installer bytes matched; with
  Homebrew and existing Boundary binaries excluded, the direct-release lane
  installed the Apple Silicon static archive after selecting exactly one
  checksum filename-field entry despite the SBOM prefix collision. The
  installed binary reported `v0.13.1` at the approved release commit and
  passed `version`, `selftest`, `hook --help`, and the fixture-only GitHub
  lethal-trifecta demo. Receipt-driven uninstall and the disposable-root
  cleanup passed, the monitored real-environment Boundary surfaces were
  unchanged, and independent read-only review returned
  `SMOKE EVIDENCE APPROVED`.
- That smoke validates only the direct-release Apple Silicon static path and
  those local fitness commands. It does not validate Homebrew installation,
  plugin or marketplace availability, routed deployment coverage,
  authenticity, execution proof, or protection of bypass paths.
- No claim upgrades on publication alone; tagged-publication evidence is
  recorded separately in `docs/RELEASE_TRUTH_PUBLIC.md`.
