# Fulcrum Boundary v0.13.0

> **Published release — 2026-08-31.** The annotated root `v0.13.0` and nested
> `verify-witnessed/v0.13.0` tags both peel to
> `8abd10be7c3f3e5a3727bb73acd0a84811431d3b`. The GitHub release is public,
> not a draft or prerelease, with 23 digest-verified assets and 22 verified
> build-provenance attestations (`SHA256SUMS-cgo` is expectedly un-attested).

**Auto mode decides. Boundary keeps the receipts.**

`v0.13.0` is the Session Receipts and Claude Code hook release. It
preserves the product boundary: MCP remains the production adapter; Command
Boundary and Edit Boundary — the classifiers the new hook routes into — remain
delivered previews; every other adapter and profile remains preview; protection
applies only to actions routed through Boundary; and Boundary does not emit
`proved` decisions.

## Highlights

- **`boundary hook pretooluse` — a binary-native Claude Code `PreToolUse`
  boundary.** Every tool call the hook is wired to intercept — `Bash`/`Shell`
  through Command Boundary, `Edit`/`Write`/`MultiEdit`/`NotebookEdit` through
  Edit Boundary — gets a pre-execution verdict, and a canonical
  `DecisionRecordV1` is persisted *before* the decision reaches Claude Code.
  `deny` blocks, `warn` and `require_approval` surface as `ask`, `allow` is
  silent, and the hook never emits a permission grant it has no standing to
  make. A record the sink cannot write escalates the call instead of allowing
  it unrecorded. Routed-only: a tool the matcher does not list, an MCP tool, a
  tool a subprocess runs on its own, and shell use outside Claude Code are
  bypasses and are not governed.
- **Session receipts you can re-verify.** Hook decision records persist under
  `BOUNDARY_HOOK_DIR` (default `.boundary/hook`) before the verdict returns;
  `boundary verify-record`, `boundary explain`, and `boundary replay` read
  them directly, and `boundary hook sessionend` appends a per-session summary
  line that gates nothing. Verification is hash recomputation over covered
  record fields — integrity, not authenticity: it shows the record was not
  altered after emission, not that the verdict was right, that execution or
  prevention occurred, or who produced the record.
- **Compound-command decomposition in Command Boundary.** A command line is
  split on shell operators, subshells, command substitution, `sh -c` payloads,
  redirects, and argument-position commands (`find -exec`, `xargs`), and the
  most restrictive segment sets the verdict — a destructive tail behind a
  benign head is no longer classified on its leading command. A line the
  decomposer cannot model is floored at `require_approval` and never allowed.
  Command Boundary stays a delivered preview.
- **Governance control surfaces denied on both routed lanes.** Writes to
  `.boundary/**`, the Claude Code settings and hook files, and the shipped
  wrapper scripts are denied on the routed edit and command lanes alike. This
  is a set of path shapes, not an inventory of every way governance could be
  disabled.
- **Plugin, installer, skills, and operator surfaces.** A repo-root Claude
  Code plugin manifest and hook wiring; `scripts/install-claude-code.sh` with
  a receipt-driven `--uninstall`; the `/boundary:drill`, `/boundary:report`,
  `/boundary:protect`, and `/boundary:verify` skills; and `boundary hook
  doctor`, which reports wiring, shadowing, dormancy, and the bypasses it
  knows about rather than claiming it is the only thing routing tool calls. A
  marketplace scaffold sits unpublished in the repository.
- **Safer defaults.** The hook fail-mode default is `ask`: on an internal
  fault Boundary declines to answer for the operator in either direction. A
  Boundary `deny` always blocks regardless of the setting.
- **Audit log redaction.** `SlogAuditPublisher` emits deterministic SHA-256
  digests instead of caller-controlled clear-text values; decision records
  keep their existing schema. GitHub Actions dependencies are pinned to
  immutable commit SHAs, enforced in CI.

## What the hook does not do

The hook governs only the tool calls it is wired to intercept. It does not
govern MCP tools, subprocesses' own commands, subagents, or shell used outside
Claude Code; it is not a sandbox, does not contain the agent, and does not
detect prompt injection in tool inputs. It runs alongside — not instead of —
Claude Code's own permission system. Coverage of a session is exactly the set
of calls the hook delivered, no more.

## Install

```bash
brew install fulcrum-governance/tap/boundary
docker pull ghcr.io/fulcrum-governance/boundary:v0.13.0
go install github.com/fulcrum-governance/fulcrum-boundary/cmd/boundary@v0.13.0
```

Install the nested verifier from its source-distribution tag:

```bash
go install github.com/Fulcrum-Governance/Fulcrum-Boundary/verify-witnessed@v0.13.0
```

The verifier does not have its own prebuilt archive, container, Homebrew
package, or version flag.

## Compatibility and limitations

- This is a pre-1.0 release. Read `CHANGELOG.md` for the full
  `v0.12.0..v0.13.0` delta, including the behavior changes: `warn` and
  `require_approval` now prompt instead of passing silently, control-surface
  writes deny even when the surface is the copy *source*, benign `find -exec`
  idioms can now prompt, and the hook fail-mode default moved from open to
  `ask`.
- Direct tool paths that bypass Boundary remain outside its control.
- Secure GitHub, Command Boundary, Edit Boundary, CLI, CodeExec, gRPC, Managed
  Agents, Webhook, and A2A remain preview.
- No claim upgraded on publication alone; the tagged-publication evidence is
  recorded in `docs/RELEASE_TRUTH_PUBLIC.md`.
