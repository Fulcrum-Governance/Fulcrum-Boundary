# Fulcrum Boundary v0.14.0

> **Published release — 2026-11-05.** The public
> [GitHub release](https://github.com/Fulcrum-Governance/Fulcrum-Boundary/releases/tag/v0.14.0)
> is not a draft or prerelease. The annotated `v0.14.0` and
> `verify-witnessed/v0.14.0` tags both peel to
> `a64f4f67c22e1416a4a20fdeb4b3c2d54af44379`. Publication facts are recorded
> in `docs/RELEASE_TRUTH_PUBLIC.md`.

`v0.14.0` turns on decision records by default for routed calls on the
production MCP route (`boundary serve`), makes every adapter fail closed the
same way on enforcing routes when a required check cannot run, and fixes
several cases where a `warn` or a malformed rule let a routed call run that
should have been held. It preserves the product boundary: MCP remains the only
production adapter; Command Boundary, Edit Boundary, Secure GitHub, CLI,
CodeExec, gRPC, Managed Agents, Webhook, and A2A remain preview; and Boundary
does not emit `proved` decisions.

Scope: Boundary decides before execution only for actions forced through a
governed Boundary route. Every item below applies only to those routed
actions. Tool paths that bypass Boundary remain outside its control.

Each item is labeled:

- **implemented**: a product behavior change in this release, with tests.
- **tested**: test, CI, or evidence coverage only; no product behavior change.
- **refactor**: code change with no behavior change.
- **docs**: documentation only.

"Enforcing routes" excludes dry-run and transports declared non-enforcing,
which log a would-be block instead of blocking.

Decision records are hash-verifiable for covered-field integrity only. They
do not establish authenticity, signing, verdict correctness, enforcement, or
completeness.

## Highlights

- **implemented** — `boundary serve` writes a decision record for each
  decision it makes on a routed call, on by default (#266). Each record is
  written under `DIR/records/` and appended to `DIR/decision-records.jsonl`,
  in the same
  `DecisionRecordV1` shape `boundary verify-record` checks. `DIR` defaults to
  `.boundary/serve`; `--record-dir` / `server.record_dir` override it and
  `--no-records` / `server.records: false` turn records off. The
  source-built image (`Dockerfile`) passes `--record-dir
  /var/lib/boundary/serve`; the published release image runs `selftest` by
  default and, if run as `serve`, uses the default `.boundary/serve` under
  `/home/nonroot`. A record that cannot be written
  counts as an audit delivery failure; it never changes the decision.
- **implemented** — `boundary serve --dry-run` and `security.dry_run` (#265).
  A would-be `deny` or `check_indeterminate` is logged with its real verdict
  and `dry_run: true`, then let through; `escalate`, `require_approval`, and
  configuration-error `check_indeterminate` outcomes still hold the call. Dry-run turns off blocking for `deny` and
  `check_indeterminate`; it is for rehearsing a policy, not for routes where
  enforcement is required.
- **implemented** — The most restrictive matching static rule decides (#264):
  `deny` > `require_approval` > `escalate` > `warn` > `audit` > `allow`. A
  `warn` rule no longer masks a `deny` or the built-in Postgres guard.
- **implemented** — Required-check failures are classified
  `check_indeterminate` (ADR-047) in the shared pipeline and block execution
  (#226, #252). Policy-evaluation faults, a nil evaluator fallback, a nil
  pipeline (#272), and a static rule action the pipeline would skip (#270) now
  fail closed as `check_indeterminate` instead of allowing or reporting a
  policy `deny`.

## Changed and fixed

- **implemented** — Release builds and CI use Go 1.26.10, which fixes
  standard-library advisory GO-2026-6809 (`crypto/x509`), reported by
  `govulncheck` against Go 1.26.9. The `verify-witnessed` module now requires
  Go 1.26.10.
- **implemented** — A `warn` no longer lowers an agent's trust score (#261).
- **implemented** — Unknown rule actions are rejected at policy load in the
  legacy static shape (#263).
- **implemented** — CLI and CodeExec report the verdict that blocked the
  command or code in `x-fulcrum-action` (#271); the Secure GitHub MCP route
  does the same in its JSON-RPC error data (#273).
- **implemented** — The Secure GitHub fallback decision record carries the
  check context (#274).
- **implemented** — `boundary command run` classifies `find -exec`/`xargs`
  and wrapper forwarding by the more restrictive of forwarder and payload
  (FUL-653, #250).
- **implemented** — The hook classifies absolute-path commands by trusted bin
  directories (#224, landed via #232).
- **implemented** — All four shipped decision-record verifiers ingest
  strictly and identically: duplicate keys, trailing data, and unknown members
  are rejected (#228).
- **implemented** — The Secure GitHub live evidence index recomputes the
  transcript digest from disk (FUL-708, #240).
- **implemented** — CodeExec named OCI container sandbox (#229). The CodeExec
  adapter stays preview.
- **refactor** — Unreachable `Evaluate` error branches removed from the
  adapters (#275).

## Install

The Homebrew cask now installs `v0.14.0`.

```bash
brew install fulcrum-governance/tap/boundary
docker pull ghcr.io/fulcrum-governance/boundary:v0.14.0
go install github.com/fulcrum-governance/fulcrum-boundary/cmd/boundary@v0.14.0
```

Install the nested verifier from its source-distribution tag:

```bash
go install github.com/Fulcrum-Governance/Fulcrum-Boundary/verify-witnessed@v0.14.0
```

The verifier does not have its own prebuilt archive, container, Homebrew
package, or version flag.

The public install smoke passed on 2026-11-05. It covered `go install` of both
modules, the `darwin_arm64` static archive checksum, a GitHub attestation
verification, and the container image `selftest`. It did not run `brew
install`, and it does not validate the plugin or marketplace, routed
deployment coverage, authenticity, execution proof, or protection of bypass
paths. The public `boundary-plugins` marketplace was updated to `v0.14.0` and
validated separately; see `docs/RELEASE_TRUTH_PUBLIC.md`.

## Compatibility

- `boundary serve` now creates `.boundary/serve` in its working directory by
  default. Pass `--no-records` to keep the previous stdout-only behavior, or
  `--record-dir` to choose another directory. A directory that cannot be
  created makes serve exit 1 before the listener opens. serve tightens an
  existing record directory to `0700` and refuses a symlink, a non-directory,
  or a directory owned by another user.
- Policy files with an unknown rule action in the legacy shape now fail to
  load instead of silently allowing.
- Adapters that previously reported `deny` for a blocked call may now report
  `require_approval`, `escalate`, or `check_indeterminate`. The block itself is
  unchanged.
- This is a pre-1.0 release. See `CHANGELOG.md` for the full
  `v0.13.1..v0.14.0` delta.
- No claim upgrades on publication alone; tagged-publication evidence is
  recorded separately in `docs/RELEASE_TRUTH_PUBLIC.md`.
