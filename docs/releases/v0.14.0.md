# Fulcrum Boundary v0.14.0

> **Release candidate — not yet tagged.** Target tag date 2026-10-22. The
> tag, release commit, assets, and publication facts are recorded in
> `docs/RELEASE_TRUTH_PUBLIC.md` after publication, not here.

`v0.14.0` makes decisions on the production MCP route verifiable by default,
makes every adapter fail closed the same way when a required check cannot run,
and fixes several cases where a `warn` or a malformed rule let a call run that
should have been held. It preserves the product boundary: MCP remains the only
production adapter; Command Boundary, Edit Boundary, Secure GitHub, CLI,
CodeExec, gRPC, Managed Agents, Webhook, and A2A remain preview; and Boundary
does not emit `proved` decisions.

Scope: Boundary decides before execution only for actions forced through a
governed Boundary route. Every item below applies only to those routed
actions. Tool paths that bypass Boundary remain outside its control.

Each item is labeled:

- **implemented**: a behavior change shipped in this release, with tests.
- **tested**: test, CI, or evidence coverage only; no product behavior change.

Decision records are hash-verifiable for covered-field integrity only, not
authenticity, correctness, or execution proof.

## Highlights

- **implemented** — `boundary serve` writes a decision record for every
  routed decision, on by default (#266). Each record is written under
  `DIR/records/` and appended to `DIR/decision-records.jsonl`, in the same
  `DecisionRecordV1` shape `boundary verify-record` checks. `DIR` defaults to
  `.boundary/serve`; `--record-dir` / `server.record_dir` override it and
  `--no-records` / `server.records: false` turn records off. The container
  image writes to `/var/lib/boundary/serve`. A record that cannot be written
  counts as an audit delivery failure; it never changes the decision.
- **implemented** — `boundary serve --dry-run` and `security.dry_run` (#265).
  A would-be `deny` or `check_indeterminate` is logged with its real verdict
  and `dry_run: true`, then let through; `escalate` and `require_approval`
  still hold the call.
- **implemented** — The most restrictive matching static rule decides (#264):
  `deny` > `require_approval` > `escalate` > `warn` > `audit` > `allow`. A
  `warn` rule no longer masks a `deny` or the built-in Postgres guard.
- **implemented** — Required-check failures are classified
  `check_indeterminate` (ADR-047) in the shared pipeline and block execution
  (#226, #252). Policy-evaluation faults, a nil evaluator fallback, a nil
  pipeline (#272), and a static rule action the pipeline would skip (#270) now
  fail closed as `check_indeterminate` instead of allowing or reporting a
  policy `deny`.

## Changed and fixed

- **implemented** — A `warn` no longer lowers an agent's trust score (#261).
- **implemented** — Unknown rule actions are rejected at policy load in the
  legacy static shape (#263).
- **implemented** — CLI and CodeExec report the verdict that blocked the
  command or code in `x-fulcrum-action` (#271); the Secure GitHub MCP route
  does the same in its JSON-RPC error data (#273).
- **implemented** — The Secure GitHub fallback decision record carries the
  check context (#274).
- **implemented** — `boundary command run` classifies `find -exec`/`xargs`
  and wrapper forwarding by the more restrictive of forwarder and payload
  (FUL-653, #250).
- **implemented** — The hook classifies absolute-path commands by trusted bin
  directories (#224, restored in #232).
- **implemented** — All four shipped decision-record verifiers ingest
  strictly and identically: duplicate keys, trailing data, and unknown members
  are rejected (#228).
- **implemented** — The Secure GitHub live evidence index recomputes the
  transcript digest from disk (FUL-708, #240).
- **implemented** — CodeExec named OCI container sandbox (#229). The CodeExec
  adapter stays preview.
- **implemented** — Unreachable `Evaluate` error branches removed from the
  adapters (#275).

## Compatibility

- `boundary serve` now creates `.boundary/serve` in its working directory by
  default. Pass `--no-records` to keep the previous stdout-only behavior, or
  `--record-dir` to choose another directory. A directory that cannot be
  created makes serve exit 1 before the listener opens.
- Policy files with an unknown rule action in the legacy shape now fail to
  load instead of silently allowing.
- Adapters that previously reported `deny` for a blocked call may now report
  `require_approval`, `escalate`, or `check_indeterminate`. The block itself is
  unchanged.
- This is a pre-1.0 release. See `CHANGELOG.md` for the full
  `v0.13.1..v0.14.0` delta.
